# ADR 0008 — Runtime pacing, control and publishers

Every tick propagates to one absolute UTC and creates one ordered state batch in memory. Standalone deadlines use wall time and the configured clock rate maps elapsed time to simulation UTC. Missed wall deadlines are skipped. External deadlines use successive authoritative timestamps and catch up by publishing the current due state once. The first tick, resume, explicit seek while running and mission endpoint request a batch from every active publisher. Seek while paused updates time and delays emission until resume. Absolute propagation makes replay independent of prior steps.

Workers consume shared batches with independent queues holding up to two pending batches each. Full queues drop the incoming batch and increment a counter. A sink fault that could have delivered a partial batch disables that worker. A healthy worker continues. Startup requires each configured publisher to initialize. On stop or SIGINT/SIGTERM, the runtime closes queues and allows up to three seconds per worker to finish. Shutdown logs tick, state, propagation-error and per-worker acceptance, drop and error counts. UDP acceptance and Zenoh submission acknowledge local handling. Monitor subscriber counts for delivery validation.

DIS uses the numeric destination from the verified scenario, one UDP datagram per Entity State PDU. The registry accepts space-platform classifications and defaults to SISO Platform/Space, country and subtypes unspecified. The manifest maps sorted NORAD IDs one-to-one to sequential 16-bit entity numbers under the configured site and application IDs. Packet markings carry decimal NORAD for diagnostics. Entity attitude is zero and fixed. DRM FPW supplies a constant world-frame velocity model between messages. The time field reports absolute simulation UTC as a fraction of the hour with the absolute bit set. UDP multicast is explicit, with IPv4 TTL 1.

Zenoh v1 submits one Protobuf batch to the selected local router over TCP using drop congestion control. Receiver queues and network delivery can drop messages independently of HOTH's bounded worker queues. If Zenoh reports no connected router, the worker counts the batch as dropped and can resume submissions after reconnection. Zenoh discovery is disabled. The control adapter uses a separate mock protocol and isolated socket. See the [FABRIC integration contract](../architecture/fabric-integration.md).
