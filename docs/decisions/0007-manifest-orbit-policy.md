# ADR 0007 — Manifest, orbit initialization and radar selection

Use the source epoch and B* when both mission endpoints are within seven days of the source epoch. Otherwise initialize SGP4 at mission start with the original mean elements, including the original mean anomaly, and set effective B* to zero. Moving the epoch keeps the catalog's orbital populations representative without extrapolating drag across years. The source epoch, source bytes and B* remain in the manifest. The synthetic epoch is carried in canonical and Protobuf provenance.

Use SGP4 WGS-72 with the AFSPC compatibility convention. Rotate TEME through Greenwich mean sidereal time using IAU 1982 GMST. Approximate UT1 by UTC and set both pole coordinates to zero. Earth-fixed velocity is rotated TEME velocity minus the cross product of Earth rotation and the rotated position. UTC offsets normalize to UTC. Scenario UTC uses POSIX seconds. Earth orientation parameters, leap-second instants and geodetic truth reconstruction are outside this frame model. At the maximum nominal UTC–UT1 difference of 0.9 seconds, the sidereal approximation alone can shift a 7,000 km position by about 460 m. Reference tests use the same EOP assumptions and independently computed vectors.

Select from the closed mission interval and union all radar fields of view. Use stationary WGS-84 geodetic radar positions and local east, north, up axes. Cover the full interval with pieces up to 30 seconds long. Bound the trajectory around each midpoint by a ball of radius 25 km/s times half the interval plus 1 mm. Discard an interval when each radar has at least one gate that excludes the ball. Split ambiguous intervals until they reach 125 ms or less. Include still-ambiguous passes conservatively. The residual spatial allowance is at most about 1.56 km at the final interval resolution. The bound assumes supported Earth satellite trajectories keep Earth-fixed speeds within 25 km/s. An observed sample above that limit retains the object conservatively. This is a numerical screen with a documented speed assumption; unusual high-energy trajectories need a separately validated bound. One selected membership serves the whole mission.

Use manifest JSON v1 with a SHA-256 digest over a deterministic compact JSON serialization of its payload. Include the exact scenario YAML and its own digest, reference to the snapshot, the exact orbital record and provenance, initialization, DIS IDs, selection method and rejected-object diagnostics. Runtime recomputes the digest and reparses selected records. The digest detects accidental changes. Use the storage policy of the execution environment for authenticity. Re-preparing an identical scenario from the same inputs produces identical bytes. A prepared file is written atomically and requires a fresh output path.

Preserve existing scenario YAML v1 field spellings and numeric network destinations. New files can opt into radar union, Zenoh, explicit DIS identity, and multicast. Validate publisher rates against the runtime range 0.001–1000 Hz. See the [YAML contract](../interfaces/scenario-yaml.md) for the added fields.
